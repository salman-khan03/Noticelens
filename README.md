# NoticeLens

**Upload the notice. Understand what matters. Verify every claim. Know what to do next.**

A working local prototype for Texas tenant notices: notices to vacate, lease-violation notices, and security-deposit disputes. NoticeLens turns uploaded text/PDFs into a traceable overview and organization checklist. Its **Proof Gate** blocks unsupported statements instead of treating citation presence as proof.

## What works

- Next.js + TypeScript interface with a complete synthetic demo and three fictional notices.
- PDF text extraction; JPEG/PNG and scanned PDF OCR when Tesseract is installed.
- Paste-text fallback, recoverable errors, loading and unknown-document states.
- Extracted party/date/amount passages, approved official sources, expandable claim evidence.
- Gate rejects invented URLs, missing jurisdiction, altered quotes, unsupported claims, stale/tampered sources and a registered contradiction.
- Per-analysis safety metrics, measured small evaluation, editable informational draft, checklist, JSON export and printable packet.
- Tamper-evident verification receipts with an analysis digest, source-manifest digest, policy version, source age, and stage-by-stage audit trail.
- Privacy review that detects common personal-data patterns; export defaults to a minimized packet with a separate explicit full-document option.
- Human review status stays visible in the receipt and packet, so downstream systems cannot mistake automation for a legal decision.
- FastAPI/Pydantic API, Zod frontend validation, tests and GitHub Actions workflow.

## Run locally

Requires Node 22.13+ and Python 3.12+. From this directory:

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r backend/requirements.lock.txt
cd frontend
npm ci
cd ..
```

Terminal 1, project root:

```powershell
.venv/Scripts/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Terminal 2:

```powershell
cd frontend
npm run dev
```

Open http://127.0.0.1:3000. Select **Load sample notice**. No API key or database is required. On macOS/Linux substitute `.venv/bin/python` for `.venv/Scripts/python`.

Optional OCR: install Tesseract from an official/reputable distribution and ensure `tesseract` is on PATH. The supplied Dockerfile installs it. The current host did not have Tesseract; image/scanned-PDF uploads explain how to use text/PDF fallback rather than pretending extraction succeeded.

The evaluation page reads `sample-data/evaluation-results.json`, generated by actual runs, not marketing constants. Its six engineered cases and three synthetic notices do not establish real-world legal accuracy.

## Source provenance

`sources/manifest.json` stores the exact normalized official passages, URL, jurisdiction, retrieval timestamp and SHA-256. Official sources: [Chapter 24](https://tcss.legis.texas.gov/resources/pr/htm/pr.24.htm) and [Chapter 92](https://tcss.legis.texas.gov/resources/pr/htm/pr.92.htm). Text is a dated snapshot, not a live freshness guarantee. The gate blocks sources older than 90 days. Refresh into a review file and review the rule mappings before replacing the approved manifest.

## Deployment

- Frontend: import `frontend/` into Vercel; set server-only `API_URL` to your backend HTTPS origin. No secrets are sent to the browser.
- Backend: deploy the root-context `backend/Dockerfile` to Render or a comparable container host. Set `ALLOWED_ORIGINS` to your frontend origin. Health check: `/health`.
- Add an edge request-size limit, shared rate limiter, isolated parser worker and retention/consent review before opening uploads publicly. The demo intentionally has no auth or document persistence.
- Optional Neon: `sources/001_sources.sql` creates source-only PostgreSQL full-text search storage. The default app is not connected to Neon; no infrastructure or paid resources were created.

## Current limitations / what is not live

This first pass uses transparent deterministic rules, **not an LLM**. The provider protocol is implemented, but remote inference and credential provisioning remain to be integrated. Classification and extraction are narrow patterns, not general document understanding. The source selector is a curated lookup, not semantic RAG. The draft is an editable template; it is never sent. No legal deadline arithmetic, validity determination, legal strategy, federal eligibility analysis or legal representation is performed. OCR can be inaccurate. Sources and rule mappings have engineering checks, not attorney certification.

Next highest-impact tasks: (1) Texas legal expert review and broader adversarial/realistic fixtures; (2) consented structured LLM extraction behind the same gate; (3) connect Neon retrieval and deploy an isolated, resource-limited OCR worker.
